# Rawgenzo

Apple Silicon の Mac でネイティブに動く RAW 現像ソフトです。

- 公式ページ: https://rawgenzo.github.io
- ソースコード: https://github.com/Rawgenzo/Rawgenzo

## 特徴

- Apple Silicon ネイティブ。デコードは macOS の Core Image、補正処理の一部は Metal で行う
- 非破壊編集。現像設定は RAW の隣に `<RAW名>.rawgenzo.json` として保存し、RAW そのものは書き換えない
- 露出・ホワイトバランス・コントラスト・HDR 風トーン(ハイライト/シャドウ)・彩度
- シャープネス・ノイズ除去
- ARW に記録された補正値によるレンズ補正(周辺減光・歪曲・倍率色収差)
- 傾き補正・クロップ(枠は常に回転後の画像の内側に収まる)
- ルック(〜風フィルター)。組み込みのほか `.cube`(3D LUT)を追加できる
- 構図ガイド(三分割・黄金比・白銀比・黄金螺旋など)
- JPEG / HEIF / 16bit TIFF / HDR HEIF で書き出し。ファイル名はテンプレートで決められる
- フォルダ単位で一括現像できるコマンドラインツール `rawdev`

## 対応カメラ

現在は **SONY α7S III (ILCE-7SM3) の ARW のみ**です。他の機種のファイルは開けません。
機種は後から追加できる設計にしてあります(「開発」の節)。

## 動作環境

- Apple Silicon の Mac
- macOS 13 以降
- ビルドに Xcode 27 以降 (Swift 6.4)。外部の依存パッケージはありません

## 現状について

開発中のソフトです。設定やサイドカーの形式は互換性に気を付けていますが、変わる可能性があります。

- ビルド済みのアプリは配布していません(Developer ID 署名・公証をしていないため)。ソースからビルドしてください
- アプリでの一括現像はまだできません(CLI ではできます)
- HDR で書き出す場合も、プレビューは SDR で表示します
- 強い HDR 風トーンで、明暗差の大きい輪郭にハローが出ることがあります
- サムネイルは RAW に埋め込まれた JPEG なので、現像結果を反映しません
- 周辺減光の補正の強さが実際のレンズと合っているかは、まだ確かめていません

## インストール(ソースからビルド)

```sh
git clone https://github.com/Rawgenzo/Rawgenzo.git
cd Rawgenzo
./scripts/make-app.sh --install
```

リリースビルドして `Rawgenzo.app` を作り、自分の Mac 用の署名(アドホック署名)をして `/Applications` に入れます。
`--install` を付けなければ `build/Rawgenzo.app` を作るだけです。

ビルドせずに試すなら:

```sh
swift run RawgenzoApp
```

## 使い方

1. 「ファイル」→「フォルダを開く…」(⌘O)で ARW の入ったフォルダを開く
2. 左の一覧から写真を選び、右側の調整パネルで調整する。調整は自動で保存される
3. 「ファイル」→「書き出し」(⌘E)で書き出す

調整パネルのスライダーは、右端の「↶」で初期値に戻ります。

## コマンドラインツール (rawdev)

アプリと同じ現像エンジンをコマンドラインから使えます。フォルダを渡すと中の RAW をまとめて現像します。

```sh
swift run rawdev check                   # この Mac の Core Image が α7S III に対応しているか
swift run rawdev info <フォルダ>          # メタデータ・カメラ判定・レンズ補正値を表示
swift run rawdev develop <フォルダ> --exposure 0.5 --hdr 0.6 --look builtin.film
swift run rawdev develop <フォルダ> --aspect 16x9 --angle 1.5 --look builtin.cinema --look-strength 0.7
swift run rawdev develop <フォルダ> --hdr-output --format heif-hdr
swift run rawdev looks                   # 使えるルックの一覧
swift run rawdev config                  # 設定ファイルの書き出し設定を表示
swift run rawdev                         # オプションの一覧
```

出力先と形式は、指定しなければアプリの書き出し設定に従います(未設定なら RAW と同じフォルダの `developed/`)。
`--save` を付けると、その設定を写真のサイドカーに保存します。

`swift build -c release` でビルドした `.build/release/rawdev` を PATH の通った場所に置けば、`rawdev` だけで使えます。

## 設定ファイル

設定は `~/.Rawgenzo/` にまとめて保存します。アプリを入れ直しても消えません。

```
~/.Rawgenzo/
  config.json    アプリの設定(JSON。手で編集してもよい)
  Looks/         .cube ファイル(ルック)
```

`config.json` を手で編集したら、設定画面の「ファイルから読み直す」で反映します。
読めない形に壊れていた場合は `config.broken-<時刻>.json` に退避して既定値で起動します。
`"export"` の部分は CLI (`rawdev`) とも共有しています。

```json
{
  "export" : {
    "directoryMode" : "sameAsRAW",
    "subfolder" : "developed",
    "fileNameTemplate" : "{date}_{name}",
    "showDialog" : false,
    "format" : "jpeg",
    "colorSpace" : "sRGB",
    "quality" : 0.92
  },
  "lastFolder" : "/Users/you/Pictures/ARW",
  ...
}
```

## 書き出し

設定(⌘,)の「書き出し」タブで既定を決めておく。

- 保存先: RAWと同じフォルダ(+サブフォルダ) / 指定したフォルダ / 前回保存したフォルダ
- 保存ダイアログを毎回出すかどうか。出さない設定なら ⌘E ですぐ書き出す(⇧⌘E はいつでもダイアログ付き)
- 同名ファイルがあるとき: 番号を付ける (`name-2.jpg`) / 上書き
- 形式・色空間・画質

### ファイル名テンプレート

`{変数}` が値に置き換わる。拡張子は形式に合わせて自動で付く。

| 変数 | 内容 | 例 |
|---|---|---|
| `{name}` | 元のファイル名 | DSC01234 |
| `{folder}` | 元のフォルダ名 | 2026-09 Kanazawa |
| `{date}` `{date:書式}` | 撮影日 (既定 yyyyMMdd) | 20260914 |
| `{time}` `{time:書式}` | 撮影時刻 (既定 HHmmss) | 184207 |
| `{now}` `{now:書式}` | 書き出した日時 | 20261005-103000 |
| `{seq}` `{seq:桁数}` | 連番 (既定4桁、書き出すたびに進む) | 0007 |
| `{make}` `{model}` | メーカー・機種 | SONY, ILCE-7SM3 |
| `{lens}` | レンズ名 | FE 35mm F1.4 GM |
| `{iso}` `{f}` `{shutter}` `{focal}` | ISO・F値・シャッター速度・焦点距離 | 12800, 2.8, 1-250, 35 |
| `{look}` | ルック名 | フィルム風 |
| `{width}` `{height}` | 書き出し画像のサイズ | 4240, 2832 |

例: `{date:yyyy-MM-dd}_{seq:3}` → `2026-09-14_007.jpg`

- 値が無い変数は空になり、端に残った `_` `-` は取り除かれる
- `/` や `:` はファイル名に使えないので `-` に置き換わる
- `{{` `}}` で波括弧そのものを書ける

CLIで結果だけ確かめる:

```sh
swift run rawdev name "{date}_{model}_{seq:3}" <フォルダ>
swift run rawdev develop <フォルダ> --name "{date}_{name}" --out ~/Desktop/out
```

## 構図ガイド

ツールバーのガイドボタン、または「表示」→「構図ガイド」から選ぶ。複数を同時に表示でき、色で区別される。

| ガイド | 分割位置 | 色 |
|---|---|---|
| 二分割線 | 1/2 (破線) | 薄いグレー |
| 三分割線 | 1/3, 2/3 | 白 |
| 黄金比 | 0.382, 0.618 (1:φ) | 金 |
| 白銀比 | 0.414, 0.586 (1:√2) | 水色 |
| 対角線 | 四隅を結ぶ2本 | 薄紫 |
| 黄金三角形 | 対角線 + 残りの角からの垂線 (反転可) | 黄緑 |
| 黄金螺旋 | 黄金長方形の分割 + 螺旋 | オレンジ |

- ⌥⌘G: 表示/非表示
- ⇧⌥⌘G: 黄金螺旋の中心を 右下 → 左下 → 左上 → 右上 と回す
- クロップ中はガイドがクロップ枠の中に描かれる
- 不透明度と線の太さは「設定」(⌘,) で変更できる

## 調整パネル

右側の調整パネルのセクション(「基本」「レンズ補正」など)は、見出しの行をクリックすると折りたためる。

- 見出しの左の ▶ が、開いているときは ▼ になる
- ⌥ を押しながらクリックすると、全セクションをまとめて開閉する
- 折りたたんだ状態は設定ファイル(config.json)に保存され、写真を切り替えても次に起動しても保たれる

## コントラスト

右側の調整パネルの「基本」にある。明るい所と暗い所の差(写真全体のメリハリ)を −120〜+120 で変える。

- 見た目の明るさの上で、中間グレーを軸にした S 字のトーンカーブを掛ける。黒・白・中間グレーの明るさは変わらない
- 上げると暗い所はより暗く、明るい所はより明るくなる。下げると全体が平坦になる
- 明るさ(輝度)にだけ掛けて色の比率は保つので、色相はずれない
- CLI では `--contrast <-1.2...1.2>`(アプリの −120〜+120 に当たる)
- macOS の RAW デコーダにもコントラストの設定はあるが、α7S III の ARW では効かないので自前で実装している

## ディテール(シャープネス・ノイズ除去)

右側の調整パネルの「ディテール」にある。どちらも macOS の RAW デコーダの機能を使っている。

| 項目 | 範囲(初期値) | 内容 |
|---|---|---|
| シャープネス | 0〜600(100) | 輪郭をくっきりさせる |
| 輝度ノイズ除去 | 0〜100(ISO に応じて自動) | 高感度で出るザラつきを減らす。上げすぎると細部も消える |
| 色ノイズ除去 | 0〜200(50) | 暗部などに出る色のまだらを減らす。100 を超えた分の効きは小さい |

- **シャープネスは拡大表示(⌘0 など)と書き出しでだけ効く**。デコーダが縮小して描くときにはシャープネスを掛けないため、
  ウインドウに合わせた表示ではスライダーを動かしても見た目が変わらない
- 輝度ノイズ除去の初期値は、デコーダが ISO に応じて決める(α7S III では ISO 100 以下で 0、ISO 8000 で 30、12800 で 60 程度)。
  低感度ではノイズが少ないので、動かしてもほとんど変わらない。100 を超えると効き方が逆になるので 100 まで
- 右端の「↶」で初期値(デコーダの既定値)に戻る
- CLI では `--sharpness <0...6>`、`--luma-nr <0...1>`、`--color-nr <0...2>`

## レンズ補正

ARW に記録された補正値(撮影したときの焦点距離・絞りに合わせてカメラが記録したもの)で、
次の 3 つを補正する。右側の調整パネルの「レンズ補正」で、写真ごとにオン・オフできる。

| 補正 | 内容 |
|---|---|
| 周辺減光 | 四隅が暗くなるのを明るくする |
| 歪曲 | 広角側の樽型・望遠側の糸巻き型の歪みを直す |
| 倍率色収差 | 画面の端で赤・青がずれて色の縁が出るのを直す |

- 初めは**撮影時のカメラの設定**に従う(カメラのメニューの「レンズ補正」で「オート」にしていたものが掛かる)。
  チェックを触るとその写真用の設定になり、「カメラの設定に戻す」で戻せる
- 糸巻き型の歪みを直すと四隅に画像の無い所ができるので、そうならない分だけ全体を少し拡大する(サンプルでは最大 1.5% 程度)
- 補正値の無いレンズ(電子接点の無いレンズなど)では補正できない。パネルに「補正情報がありません」と出る
- CLI では `--lens camera`(既定)/ `all` / `off` / `v,d,ca` の組み合わせで指定する。`rawdev info` で補正値の有無と量を確かめられる
- 補正値を補正量に換算する式は、darktable がリバースエンジニアリングで求めたものを参考にした
  (詳しくは `docs/sony-lens-correction.md`)。周辺減光の補正の強さが実際のレンズと合っているかは、まだ確かめていない

## 表示の拡大・縮小

| 操作 | ショートカット | 内容 |
|---|---|---|
| ウインドウに合わせる | ⌘9 | 写真全体をウインドウに収める |
| 実際のサイズ | ⌘0 | 等倍(写真の1ピクセル = 画面の1ピクセル) |
| 拡大 / 縮小 | ⌘+ / ⌘− | 25 → 50 → 100 → 200 → 400% と段階的に変わる |
| ピンチ / ⌘+スクロール | | カーソルの位置を中心に、倍率を連続的に変える |
| ダブルクリック | | 「ウインドウに合わせる」⇔「実際のサイズ」(クリックした所がカーソルの下に残るように拡大) |
| ドラッグ / 2本指スクロール | | 拡大中に表示位置を動かす |

- 「実際のサイズ」は画面の**物理ピクセル**が基準(Lightroom の 1:1 と同じ)。Retina ディスプレイでは、
  プレビュー.app の「実際のサイズ」(ポイントが基準)の半分の大きさに見える
- 今の倍率はツールバーに表示され、押すと倍率を選べる
- 拡大して写真がはみ出しているときは、カーソルが手の形になり、ドラッグで動かせる
- 写真を切り替えても、倍率と表示位置(写真に対する割合)はそのまま。連写で同じ場所を見比べられる
- 拡大して画面の解像度がプレビュー用の解像度(長辺 2400 ピクセル)を超えると、写真全体を等倍で描き直す。
  描き直すまでの一瞬はぼやけて見える。200% 以上ではピクセルをぼかさずにそのまま拡大する
- クロップ枠の調整中は「ウインドウに合わせる」に固定される

## クロップと傾き補正

右側の調整パネルの「クロップ」で行う。「枠を調整する」を押すと、プレビューに枠が出る。

- 枠は中をドラッグで移動、四隅のハンドルで大きさを変える。「比率」を選ぶと、その比率で中央に最大の枠を作る
- 「傾き補正」(±15°)で画像を回転する。回転すると四隅に画像の無い部分ができるが、**枠は常に画像の内側に収まる**
  - 傾けたとき、枠がはみ出す場合だけ、中心と比率を保ったまま縮む。はみ出さなければ大きさは変わらない
  - 傾きを戻すと、傾ける前の枠の大きさに戻る(途中で枠を手で動かした場合は、そのときの枠が基準になる)
  - 枠を動かしたり大きさを変えたりしても、画像の外にははみ出さない(縁に沿って止まる)
- 「収まる最大まで広げる」: 今の比率のまま、画像に収まる最大の大きさにする。傾けたあとで余白が残ったときに使う。
  広げるために枠の位置がずれることがあるが、ずらす量は収まる範囲で最小にする
- 以前の版で保存した、四隅が透明になる枠はそのまま開く。枠か傾きに触ったときに内側へ収め直す

CLI の `--crop` `--aspect` `--angle` も同じく、画像に収まるよう枠を合わせる。

## ルック(〜風フィルター)

組み込みのルック(フィルム風・シネマ風・モノクロ・ノスタルジック)に加えて、`.cube` ファイル(3D LUT)を
`~/.Rawgenzo/Looks/` に置くとルックとして使える。

### 付属の LUT(LUT_examples)

`LUT_examples/` にすぐ使える `.cube` ファイルを 21 個入れてある(33×33×33、入力は sRGB ガンマ)。

| 接頭辞 | 系統 | 例 |
|---|---|---|
| `01`〜`08` | 定番の色調 | ティール&オレンジ、ブリーチバイパス、マット、クロスプロセス |
| `C01`〜`C10` | 映画風 | ティールノワール、ネオンナイト、プリントフィルム、モノクロノワール |
| `S01`〜`S03` | 季節 | 桜、夕焼け、紅葉 |

使い方:

```sh
mkdir -p ~/.Rawgenzo/Looks
cp LUT_examples/*.cube ~/.Rawgenzo/Looks/
```

1. 上のコマンドでルックの置き場にコピーする(使いたいものだけコピーしてもよい)
2. アプリを再起動する(ルックは起動時にだけ読み込まれる)
3. 右側の調整パネルのルック一覧に、組み込みのルックの下に区切り線を挟んで名前順で並ぶ。
   「強さ」で効き具合を調整できる

CLI では `cube:<ファイル名>` で指定する:

```sh
swift run rawdev looks       # 読み込まれたルックの ID と名前の一覧
swift run rawdev develop <フォルダ> --look cube:01_TealOrange_Cinematic.cube --look-strength 0.6
```

- 一覧に出る名前は、ファイル内の `TITLE` があればそれ、なければファイル名
- 写真ごとの設定(`.rawgenzo.json`)には `cube:<ファイル名>` で保存される。**ファイル名を変えたり消したりすると、
  その写真ではルックが掛からなくなる**(エラーにはならず、ルック無しで現像される)
- 自作や市販の `.cube` も同じように置けば使える。ただし対応しているのは 3D LUT だけで、入力が sRGB ガンマのもの。
  Log 素材用(S-Log3 など)の LUT は、この現像結果に掛けると色が大きく崩れる

### 構成

```
Sources/RAWCore/            現像エンジン (UI非依存)
  Camera/                   対応カメラの定義と登録
    Sony/SonyA7S3Profile    α7S III の判定・初期値
  Decode/                   RAWデコーダ (現在は Core Image の CIRAWFilter)
  Lens/                     レンズ補正
  Pipeline/                 デコード後の処理 (HDRトーン → コントラスト → 色 → クロップ → ルック)
  Look/                     〜風フィルター
  Sidecar/                  現像設定を <RAW名>.rawgenzo.json に保存 (非破壊)
  Export/                   JPEG / HEIF / 16bit TIFF / HDR HEIF
Sources/rawdev/             CLI
Sources/RawgenzoApp/        SwiftUIアプリ
```

処理の流れ:

```
ARW → デコード(露出・WB・NR・シャープネス) → レンズ補正 → HDRトーン(ハイライト/シャドウ) → コントラスト → 彩度
    → [機種固有] → 傾き補正・クロップ → ルック → 書き出し
```

### 拡張のしかた

#### 構図ガイドを追加する

`CompositionGuide` に準拠した型を作り、`CompositionGuides.all` に足す。
座標は表示枠に対する比率 (0...1, 左上原点) の折れ線で返せばよい。
`DiagonalGuide` が一番短い実装例。色は `GuidePalette` に追加する(未登録なら既定色)。

#### カメラを追加する

1. `Sources/RAWCore/Camera/<メーカー>/` に `CameraProfile` 準拠の型を作る
   (`matches` でメーカー名・機種名を判定)
2. `CameraRegistry.makeDefault()` に追加する

Core Image が未対応の機種は、`RAWSource` を実装した別デコーダ (LibRawなど) を
`makeSource` から返せば、アプリ側の変更なしで対応できる。

#### 〜風フィルターを追加する

方法1: コードで書く。`BuiltInLooks` に色変換の関数を1つ足すだけ。

```swift
public static let summer = ColorCubeLook(id: "builtin.summer", displayName: "夏空風") { c in
    var o = c * SIMD3(0.97, 1.0, 1.06)       // 少し青く
    o = ColorMath.sCurve(o, 0.25)
    return ColorMath.saturate(o, 1.15)
}
```

方法2: `.cube` ファイル (3D LUT) を次のフォルダに置く。起動時に自動で読み込まれる(詳しくは「ルック」の節)。

```
~/.Rawgenzo/Looks/
```

色だけでなく周辺減光や粒子なども加えたい場合は、`Look` プロトコルを直接実装する。
強さスライダーは共通の仕組みで処理されるので、実装は「強さ100%」の結果を返すだけでよい。

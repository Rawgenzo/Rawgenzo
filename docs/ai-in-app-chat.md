# アプリ内チャット(AI をアプリに内蔵する)の検討

2026-10-16 の検討メモ。**オーナーの判断で、実装は一旦見送った。** 再開するときは、このメモの「再開するときの進め方」から始める。
今の実装(外の MCP クライアントから操作する形)は [ai-mcp-architecture.md](ai-mcp-architecture.md)、
最初の検討は [ai-agent-architecture.md](ai-agent-architecture.md) にある。

## 問い

今の Rawgenzo では、ユーザは Claude Code の会話の画面で AI に頼み、AI は MCP(`rawdev mcp`)を通して Rawgenzo を操作する。
「AI 搭載」をうたう多くのソフト(Autodesk Fusion など)は、ソフト自身の画面にチャット欄を持つ。
Rawgenzo にアプリ内チャットを作る費用と意義をどう考えるか。

## 結論(2026-10-16 時点)

- 今の MCP の形を基本にしたまま、アプリ内チャットは「同じ操作面に乗るもう 1 つの入口」として小さく試作する価値はある
- ただし先に小さな一手として、アプリで今開いている写真を返す道具 `get_app_state` を作った(2026-10-16 実装済み)。
  今の Claude Code の形のままで「この写真の白飛びを抑えて」が通じるようになり、チャット欄の利点の一部が手に入った
- アプリ内チャットは今の形を置き換えるものではなく、Claude Code を使わない人のための追加の入口と位置づけるのが妥当

## 意義

| 意義 | 内容 |
|---|---|
| AI がユーザと同じものを見られる | 開いている写真・選択・表示倍率をアプリは知っている。「この写真」「今見ているところ」で話が通じる(`get_app_state` で一部は実現済み) |
| 確認と提案を画面の中で扱える | 「3 案のどれにしますか」を縮小画像付きで並べる、書き出しの確認ボタン、仮の表示で見せてから適用する、などはアプリの UI でしか作れない |
| Claude Code を使わない人に届く | 写真を撮る人の多くは Claude Code を使わない。公開ソフトとして使う人を広げるなら、ここが一番大きい |
| 費用と速さを調整しやすい | 大量の分類を安いモデルへ、急がない処理をバッチ API へ、といった判断をアプリ側でできる |

## 費用

- **会話の仕組み**: AI との往復、道具の呼び出しの実行、会話の履歴、長い会話の要約、失敗時のやり直し、
  安全上の判定で断られたとき(`stop_reason: "refusal"`)の扱い。Swift には Anthropic の公式 SDK が無いので、HTTP を直接扱う
- **認証と課金**: API キーの保管(Keychain)・削除、使った量と料金の表示、上限の案内
- **チャットの画面**: 逐次表示、道具の呼び出しの表示、画像、確認ボタン、会話の保存。画面の比重が大きく、オーナーの確認が多く要る
- **保守**: API の変化への追従。2026-10 時点でも、思考の指定(`thinking: {type: "adaptive"}`。古い `budget_tokens` は拒否される)、
  道具の強制(`tool_choice` の `any` / `tool` は現行モデルでは使えない)など、最近の変更が多い。今の形ではこの追従を Claude Code に任せられている
- **プライバシーの説明**: 写真の統計や縮小画像がクラウドに送られることを、アプリ自身が利用者に説明する立場になる

規模の感覚: 操作面・道具・MCP(当初のフェーズ 3〜5)を合わせたのと同じくらいかそれ以上。画面の比重が大きい。

## 認証の流れ(Claude の場合)

アプリ内チャットでは Rawgenzo が Anthropic の API を直接呼ぶ。使う人は **Claude.ai のアカウントではなく、API のアカウントと API キー**を用意する。

```
① ユーザ: Anthropic Console(platform.claude.com)でアカウントを作り、支払い方法を登録し、API キーを発行する
② ユーザ: Rawgenzo の設定「AI」にキーを貼る
   → macOS の Keychain に保管する(config.json には書かない。Dropbox に同期されるため)
   → 軽い呼び出し(モデルの一覧など)で接続を確かめる
③ 使うとき: Rawgenzo → 外向き HTTPS → api.anthropic.com(キーを要求のヘッダに付ける)
   → 料金は使った分だけ、その人の Console のアカウントに請求される
```

- Claude.ai の月額契約(Pro・Max)は API の利用枠を含まず、料金も別。Claude.ai の契約のログインを第三者のアプリで使わせることは、
  私たちの知る範囲では規約上できない(**再開時に最新の規約を確認すること**)
- **今の MCP の形の利点**: AI の利用料を払っているのは Claude Code なので、Pro・Max で Claude Code を使っている人は、
  API キーも追加の料金も無しに Rawgenzo の AI 機能を使える。アプリ内チャットにすると、その人たちにも API キーと従量課金を求めることになる

## ChatGPT(OpenAI)の人も使えるようにする場合

**Rawgenzo の作りは大きくは変わらない。** 変わるのは、AI と話す部分の「翻訳」だけ。

```
変わらない: 道具(RawgenzoTools)・操作面(検証・権限・取り消し・監査ログ)・アプリとの橋渡し
新しく要る: 会話の仕組み(汎用) + 相手ごとの変換部品(Anthropic 用 / OpenAI 用)
```

| 違い | 内容 |
|---|---|
| 認証 | OpenAI の API キー(platform.openai.com)。ChatGPT Plus の契約は API の利用枠にならない |
| 道具の渡し方 | 入力の形(JSON Schema)はほぼそのまま使える。OpenAI の厳密モードは「全項目を必須にする」などの制約があり、任意の項目を持つ今の形は手直しが要る |
| 会話と結果の形 | メッセージの形、道具の結果の返し方、画像の渡し方が違う。道具の結果に画像を含められるかも違う |
| その他 | 逐次表示の仕組み、エラー、断られたときの扱い、キャッシュの効き方 |

- **本当の費用は品質の確認**。これまでの試験は Claude でしか行っていない。「頼まれていない項目は変えない」「作業名を付ける」
  「目標値で指示する道具を選ぶ」といった振る舞いは、相手の AI ごとに試験し直す必要がある。説明文の手直しも相手ごとに要るかもしれない
- **今の MCP の形は、すでに他社の AI にも開いている**。`rawdev mcp` は標準的な MCP サーバーなので、MCP に対応した手元のクライアントならつなげる。
  OpenAI の Codex CLI は手元の MCP サーバーを使え、ChatGPT のアカウントで使えると理解している(**Claude Code 以外では試していない**)

## 端末内の言語モデルという選択肢

macOS の端末内の言語モデル(Apple の Foundation Models)を相手にする形もある。API キーも費用も要らず、写真の情報が外に出ない。
ただし、道具を正しく使い分けられるだけの能力があるかは試さないと分からない。新しい macOS が必要なので、要件の macOS 13 の人は使えない
(使える環境だけで有効にする)。

## 再開するときの進め方

1. **会話の仕組みは最初から「相手を差し替えられる」形で、汎用の部分(OperationSurface)に作る**。
   `AgentLoop`(往復・道具の実行・履歴・予算・中断)と、相手ごとの変換部品(`ModelProvider` のような口)に分ける。
   こうすれば「どの GUI ソフトにもチャット欄を付けられる部品」になり、最初の検討の「どこまで一般化できるか」に沿う
2. **相手は Anthropic の API から**。設定でオンにする実験機能として、画面は最小限にする。API キーは Keychain
3. **同じ指示を Claude Code から頼む場合とアプリ内で頼む場合とで、使い勝手を比べる**(これまでの試験と同じく、ログで道具の呼び出しの回数・量を比べる)
4. **OpenAI 用は 2 つ目に作る**。会話の仕組みが本当に汎用になっているかの確かめとして
5. 端末内の言語モデルは、能力を確かめる小さな試験から

### 再開前に決めること

- **誰のために作るか**: オーナー自身のためなら、今の Claude Code の形と `get_app_state` で足りている部分が多い。
  公開ソフトとして Claude Code を使わない人に届けたいなら、意義が大きくなる
- **どの相手から作るか**(上の案では Anthropic → OpenAI)
- **書き出しなど、人の確認が要る道具の確認の出し方**(今の操作面には「確認する」の段階があるが、MCP では確認の手段が無く拒否している。アプリ内なら確認ボタンを出せる)

## 確かめていないこと

- Claude.ai・ChatGPT の月額契約のログインを第三者のアプリで使えるか(規約。2026-10 時点の理解では使えない)
- OpenAI の Codex CLI など、Claude Code 以外の MCP クライアントから `rawdev mcp` を使えるか
- 端末内の言語モデルが、Rawgenzo の道具を使い分けられるか

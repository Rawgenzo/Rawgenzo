# Sony ARW 埋め込みレンズ補正値の調査メモ

レンズ補正を自前で実装するときの事前知識。2026-10-06 に `RAWsample/` の 4 枚を exiftool 11.01 で調べた結果。
2026-10-07 に、値を補正量に換算する式を darktable のソースで確認した(下の「換算の式」)。
2026-10-07 に実装した(`Sources/RAWCore/Lens/`)。下の「実装後の検証」も参照。

## 背景

- macOS の `CIRAWFilter` は α7S III の ARW で `isLensCorrectionSupported == false`(`rawdev info` で確認)。
  `DevelopSettings.lensCorrection` を渡しても何も起きない
- そのため現状のアプリ・CLI ではレンズ補正が一切掛かっていない

## 確認できた事実

4 枚すべての ARW に、レンズ補正用のタグが入っていた。カメラ側の補正設定が「切」でも、補正値自体は記録されている。

| タグ | 場所 | 内容 |
|---|---|---|
| `0x7031` VignettingCorrection | SubIFD | 撮影時のカメラ設定(Auto / Off) |
| `0x7032` VignettingCorrParams | SubIFD | 周辺減光の補正値 |
| `0x7034` ChromaticAberrationCorrection | SubIFD | 撮影時のカメラ設定 |
| `0x7035` ChromaticAberrationCorrParams | SubIFD | 倍率色収差の補正値 |
| `0x7036` DistortionCorrection | SubIFD | 撮影時のカメラ設定 |
| `0x7037` DistortionCorrParams | SubIFD | 歪曲の補正値 |

- 同じ値が暗号化された SR2SubIFD にも入っている(`0x797d` / `0x7980` / `0x7982`)。平文の SubIFD 側を読めば足りる
- 補正値の配列は、先頭の数が点の数を表すと見られる。周辺減光と歪曲は「16 + 値 16 個」、色収差は「32 + 値 32 個」
  - 色収差の 32 個は、R 用 16 個と B 用 16 個と推測している(未確認)
- MakerNote(Sony)にも `0x2011` / `0x2012` / `0x2013` として、カメラの補正設定だけが入っている
- センサーの全体は 4288×2848。DefaultCropOrigin は 12,8、DefaultCropSize は 4240×2832。
  `CIRAWFilter` の出力は 4240×2832 なので、補正の中心と半径はクロップ後の座標で考える必要がありそう(未検証)

### 値の傾向(レンズの性質と合っているか)

- 歪曲: 16mm で大きく負の値になり、35mm では小さく正の値になる。ズームの広角側が樽型、望遠側が糸巻き型という
  一般的な性質と、向きが合っている
- 周辺減光: 中心が 0 で、外側ほど単調に増える。16mm F2.8 が最も大きい
- つまり、撮影条件(焦点距離・絞り)ごとにカメラが計算した値が入っている。レンズごとの補正表を自前で持つ必要は無さそう

## 換算の式(darktable で確認、2026-10-07)

darktable の `src/iop/lens.cc`(`_init_coeffs_md_v2`、`_process_md`)と `src/common/exif.cc` で確認した。
式はリバースエンジニアリングと試行錯誤で求めたもの、と darktable の説明にある。
**darktable は GPL なのでコードは写さず、式だけを参考に自分で実装すること。**

- 読み方: 各配列の先頭が点の数 `nc`(16)。色収差は先頭が `2 * nc`(32)で、続く 16 個が R、その次の 16 個が B
  (先の推測は合っていた)。exif.cc は `nc <= 16`、色収差の先頭 = `2 * nc`、周辺減光の先頭 = `nc` を確かめてから使う
- 点の位置: `i` 番目(0 始まり)の点の半径 = `(i + 0.5) / (nc - 1)`。半径は**画像の中心から隅までの距離(半対角)を 1** とする。
  点と点の間は直線で補間し、最初の点より内側は最初の値、最後の点より外側は最後の値を使う
- 歪曲: 倍率 `d(r) = 1 + 値 × 2^-14`。出力の画素(中心からの位置 `p`、半径 `r`)は、入力の `d(r) × p` の位置の色を取る
- 倍率色収差: R と B の倍率に、それぞれ `1 + 値 × 2^-21` を掛ける(G は歪曲の倍率のまま)
- 周辺減光: `k(r) = 2^(0.5 − 2^(値 × 2^-13 − 1))`。入力の明るさを `k` で割る(リニアな値に対して)。
  値 0 なら k = 1(補正なし)。旧版(v1)は k を 2 乗していたが、今の既定(v2)は 2 乗しない
- darktable では、歪曲で画像の外を参照する分は端の画素で埋める(自動の拡大は v1 だけ)

サンプルでの手計算:
- 16mm(DSC03451)の歪曲は外周で約 −4.1%(値 −679)→ 外側ほど内側から色を取る = 樽型の補正
- 16mm F2.8 の周辺減光は外周(値 11904)で k ≈ 0.55 → 約 +0.9 EV 明るくする

## 別の情報源: lensfun(2026-10-07 に確認)

Hugin の利用者が集めていた歪曲などの補正データは、lensfun プロジェクトのデータベースとして続いている
(darktable も埋め込み値の代わりに使える)。https://github.com/lensfun/lensfun の `data/db/mil-sony.xml`

- サンプルのレンズは両方とも登録されている
  - FE 16-35mm f/2.8 GM: 歪曲(ptlens モデル、16〜35mm を 1mm ごと)、倍率色収差、周辺減光(焦点距離・絞りごと)
  - FE 50mm f/1.2 GM
- データの許諾は **CC BY-SA 3.0**(ライブラリは LGPL 3)。手元で使うのは問題ないが、このリポジトリに同梱すると
  その部分に継承の義務が付く
- 使い道:
  1. 埋め込み値の換算が正しいか(符号・半径の基準)を、**独立した情報源**として照合する
  2. 埋め込み値の無いレンズ(電子接点の無いオールドレンズ等)の代わり。ただしその場合はレンズを手で選ぶ UI が要る
- 注意: lensfun の半径の基準は埋め込み値と違う(短辺の半分を 1 とすると理解しているが、照合の前に確かめること)

## 実装後の検証(2026-10-07)

- 読み出した値は exiftool と一致(テスト `testReadsSampleARW`)
- GPU のカーネルの結果は CPU の計算と一致(座標を色に埋め込んだ画像で、0.6 画素以内。周辺減光も一致)
- **歪曲は lensfun と照合**: 16mm・19mm では、中心に対する倍率の変化の向き・形が一致し、差は 1 ポイント以内
  (半径の基準を「半対角 = 1」としたほうが、取り違えた場合より合う)。lensfun の ptlens は「高さの半分 = 1」
  (Hugin の座標)。35mm は差が 2 ポイントあるが、lensfun 自身の値が隣の焦点距離で大きく揺れている
  (34mm だけ外周 +10.7%、他は +2.6〜4.1%)ので、参考にならない
- **周辺減光の強さは未検証**。ARW の埋め込みプレビュー(1616×1080 の JPEG)は、カメラの設定が「オート」でも
  周辺減光の補正が掛かっていなかった(明るさの分布が補正なしの現像とほぼ同じ)ので、比較に使えない。
  確かめるには、均一に照らされた被写体(白い壁・雲の無い空をピントを外して)を撮った写真か、
  カメラが RAW と同時に記録した JPEG が要る
- 処理時間(Apple Silicon、α7S III): 描き直しはプレビュー 16 → 17ms、等倍 36 → 43ms。
  写真を開いて最初の描画だけ約 0.1 秒増える(カーネルのコンパイルと拡大率の計算)

## 未確認

- 周辺減光の補正の強さ(上の「実装後の検証」)
- 半径の基準となる画像の大きさ(センサー全体 4288×2848 か、クロップ後 4240×2832 か)。darktable は自分のパイプラインの
  入力画像を基準にしている。差は 1% 程度なので結果への影響は小さいと見込む
- 他の機種(将来対応する場合)でも同じタグか
- カメラ内 JPEG と比べたときに、補正結果が一致するか(埋め込みプレビューは補正が掛かっていないので使えない。
  RAW+JPEG で撮った JPEG が要る。今回のサンプルは歪曲補正が「切」で撮られているので、歪曲は比べられない)

## 実装の概要

- 読み取り: `TIFFReader`(外部依存なし)で IFD0 → SubIFDs(0x014a)→ 0x7031〜0x7037 を読む(`SonyLensCorrection`)。
  写真を開いたときに一度だけ読み、`Photo.lensCorrection` に固定値として持つ
  - ImageIO の `CGImageSourceCopyPropertiesAtIndex` では取れない(確認済み)
  - SubIFD はタグ番号順に並んでいないので、全項目を順に見る
- カメラ設定の値: 周辺減光 256 = 切 / 257 = オート / 511 = 補正値なし、倍率色収差・歪曲 0 = 切 / 1 = オート /
  255 = 補正値なし(歪曲は 17 = オート(レンズで固定) もある)。exiftool のタグ定義で確認
- 換算: `LensCorrectionData.sony`。補正の適用: `LensCorrector`(Metal の計算カーネルを CIImageProcessorKernel で組み込む)。
  デコード直後(リニアな値)に、歪曲・倍率色収差・周辺減光を 1 回で掛ける
- 糸巻き型で縁が画像の外を参照しないよう、全体を拡大する(`autoScale`。縁の点を全部調べる)
- 設定: `DevelopSettings.lens`(nil = 撮影時のカメラ設定に従う)。schemaVersion 2
